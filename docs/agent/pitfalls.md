# 已知陷阱

## Agent 工具消息不能拆分

OpenAI-compatible 消息中的 `tool` 必须紧跟声明对应 `tool_calls` 的 assistant 消息。Agent 上下文达到预算后，不能逐条截取尾部消息，否则可能保留工具结果却省略它的调用消息，导致接口返回 `Messages with role 'tool' must be a response to a preceding message with 'tool_calls'`。

`src/lib/agent/context.ts` 将带工具调用的 assistant 消息及其连续工具结果作为一个压缩组。调整上下文预算、历史恢复或消息转换时，应继续保持这个原子边界，并覆盖单次 assistant 并行调用多个工具的情况。

## 校验定位必须基于当前 revision

校验报告中的数组路径（例如世界书条目和资源索引）只对生成报告时的卡片顺序有效。Rust 复检结果在卡片 revision 改变后必须清除；导航前应重新基于当前 DOM 的 `data-validation-path` 查找目标，不要缓存节点或索引。

世界书条目使用懒挂载折叠内容。定位 `data.character_book.entries.{index}.{field}` 时，先打开当前索引条目，再等待具体字段挂载；具体字段不存在时只能聚焦条目或校验项本身。重排和删除条目后继续依赖当前索引，不要复用旧的 DOM 引用。

## 编辑台响应式断点看容器宽度

Agent 编辑台在桌面端可以独立调整宽度，窗口较宽不代表编辑页面也有足够空间。编辑台内部的表单列数、工具栏和摘要布局应使用命名为 `agent-inspector` 的 CSS container query；仅使用 viewport media query 会在窄编辑台中保留桌面布局并造成内容裁切。

## Token 统计明细在窄栏中保留指标关联

Token 统计的世界书和开场白明细在宽栏使用表格，在窄栏转换为带有指标标签的数据卡。不要只把宽表格的列机械堆叠或依赖父层 `overflow-x: hidden`，否则数值会与表头失去关联，长路径和标题也会被静默裁掉。布局断点必须使用 `agent-inspector` 容器宽度，并让每个数据单元格保留本地化的 `data-label` 或等价可读标签。

## Agent 条目 mention 不是普通单词

页面上下文同样属于 mention 权限的一部分。世界书、开场白、基础信息和提示词页不能通过手工输入另一类 token 或修改范围下拉框扩大到整卡；关闭右侧编辑台时要保留最后一个业务页面上下文。卡片页的多个精确字段/开场白/条目目标使用 `targets` 集合，必须在投影、校验报告、Token 统计和变更权限中逐项过滤，不能为了支持混合选择退回 `card` 权限。开场白使用数组索引，发送时需确认索引仍存在；群组开场白、资源、extensions 和世界书元数据目前没有对应 Agent 提案路径，不能只加入候选菜单。

世界书标题可能包含空格、标点或重复值，不能只用 `@` 后的首个无空格单词解析。自动补全插入带引号的标题；重名项额外携带一基数组序号。候选项不得在数据层截断，应由可滚动列表承载全部匹配结果。多个 mention 必须全部解析为条目集合权限，不能只保留第一个或最后一个；发送时也要保留原始文本，避免聊天记录与实际授权范围脱节。权限解析仍需对当前卡片重新核对标题或 ID，不能直接信任界面生成的序号。

## 局部 Escape 快捷键必须隔离全局监听

Agent 编辑台通过 `document` 监听 `Escape` 关闭卡片纲要。输入框或弹出列表拥有自己的 `Escape` 行为时，处理完局部状态后必须停止事件冒泡，否则一次按键会继续触发全局关闭逻辑，意外关闭仍应保留的面板。

## 空会话必须先持久化再加入历史

只在 `AgentStudio.tsx` 中生成 ID 并切换状态，会让连续创建的空会话只存在于当前渲染，下一次历史刷新后无法恢复。新会话应先调用 `save_agent_session`，再把返回的记录加入 `sessionHistory`；会话切换、右键菜单和快捷键必须复用同一个入口，并在切换/生成期间使用锁避免异步竞态。

## editable 区域要先解析专属菜单

全局上下文菜单会先识别 `textarea`/`input`。Agent 输入框如果直接走通用文本分支，就无法提供“清空输入”等 Agent 操作；应先按 `data-context-menu="agent-composer"` 解析区域目标，再复用粘贴、全选等编辑命令。消息和会话项也必须标记自身区域，否则会退回工作区菜单。

## 并行世界书提案不能只看卡片 revision

多个 Agent 提案可能读取同一版本后分别编辑不同的既有世界书条目。确认第一项会递增卡片 revision，但不应让其余未受影响条目的提案全部失效。仅当提案全部是既有条目编辑，且每个目标条目的 fingerprint 仍一致时，才可以在新 revision 上应用；卡片字段、候选注入、混合提案或目标条目已改变时仍必须拒绝。
