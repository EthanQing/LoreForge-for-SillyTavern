# SillyTavern Card Creator 使用指南

本指南对应 v0.3.0。应用默认进入 Agent Studio，右侧编辑台保留完整的手动编辑、导入导出和保存能力。

## 启动

```powershell
pnpm install
pnpm tauri dev
```

仅调试前端时运行 `pnpm dev`。Windows PowerShell 如果拦截 `pnpm.ps1`，可使用 `pnpm.cmd`。

## 创建或打开卡片

- 新建卡片会创建本地草稿和独立 workspace。
- 可打开 JSON、PNG/APNG 或 CHARX 角色卡。
- 已绑定文件的保存会写回原路径；草稿使用现有保存/导出流程选择目标格式。
- Agent 应用只修改当前草稿状态，随后沿用项目的静默保存规则；用户确认前不会改动卡片或文件。

## Agent Studio

- 左栏按角色卡 workspace 展示 Agent 会话，可新建或切换会话。
- 中栏显示当前会话、流式回复、工具轨迹、待审提案和主输入框。
- 右栏是卡片纲要与手动编辑台，可打开基础信息、提示词、开场白、世界书、资源、预览、Token 统计、校验和设置。
- 字段助手、世界书“生成候选条目”入口和主输入框共享同一个 Controller、消息记录和提案队列。

v0.3.0 不提供旧 Guide/Edit 档案界面，也不迁移旧 Agent 历史。

## 权限范围

发送前必须有一个由前端创建的权限范围：

- 整张卡片：读取和编辑已公开的卡片字段，并可生成世界书候选。
- 区块：仅限基础信息、提示词、开场白或世界书。
- 精确字段：字段助手自动使用，模型只能读取和编辑该字段。
- 整个世界书：可读取世界书、编辑现有条目允许字段并生成候选。
- 单个世界书条目：`@条目标题` 或条目字段助手生成，绑定条目索引和指纹。

输入中的 `@` 目标会在发送前解析。找不到或不唯一的条目不会退回整张卡片范围。点击“重新生成”或编辑后“重新发送”时，会使用输入区当前选中的权限范围创建新请求；这是用户主动重新授权。运行中的 steering/follow-up 仍锁定在本轮原权限，不能切换到更大的范围。

## 类型化 Agent 工具

- `inspect_card`：读取当前授权的卡片投影。
- `inspect_lorebook_entry`：读取一个已授权条目及其指纹。
- `inspect_validation`：读取当前校验报告。
- `inspect_token_usage`：读取 Token 估算。
- `propose_card_edits`：提交受类型约束的卡片字段编辑。
- `propose_lorebook_entry_edits`：编辑已有条目的允许字段，必须携带当前条目指纹。
- `propose_lorebook_injection`：生成一个或多个世界书候选。

模型不能提交权限路径，不能发送通用 JSON Patch，也没有删除工具。

## 世界书候选注入

1. 在世界书面板点击“生成候选条目”。应用会关闭编辑台、聚焦主输入框并预设世界书范围。
2. 输入候选主题、数量和要求后发送。
3. 在候选卡中审阅标题、关键词、内容摘要、启用状态、触发策略、注入位置、深度/角色、顺序、概率、Token 影响与校验错误。
4. 勾选需要的候选，点击“确认注入所选”。
5. 应用基于当前 revision 原子执行：只要卡片已变化、所选候选包含错误或权限失效，就不会写入任何候选。

注入会映射 SillyTavern 的关键词、次要关键词、正则/选择性触发、常驻/向量触发、位置 0–7、深度角色、顺序、概率、优先级、大小写敏感和 outlet 等字段。已有世界书条目的未知 CCv3 字段与 `extensions` 会保持原样。

手动编辑器仍可创建、修改和删除条目；Agent 只能修改允许字段或提出候选，不能删除。

## 提案冲突

每个提案记录创建时的卡片 revision 和稳定快照哈希；条目编辑还记录条目指纹。确认时任一值与当前状态不一致，提案会进入冲突状态，不能强制覆盖。重新让 Agent 读取当前数据并创建新提案即可。

## 设置与凭据

保留的设置包括提供商、端点、模型、系统凭据、上下文窗口、最大输出、超时、温度、thinking level、工具能力状态和不安全 HTTP 开关。流式显示、旧推理显示模式、旧连接发送路径等设置已删除。

API key 只写入系统凭据库。旧 localStorage 中的明文 key 会被忽略，不会自动迁移。

## 历史清除

首次使用 v0.3.0 的 Agent 历史功能时，后端只删除应用数据目录中精确匹配的：

- `ai_chat_history.sqlite3`
- `ai_chat_history.sqlite3-wal`
- `ai_chat_history.sqlite3-shm`

随后创建全新的 `agent_history.sqlite3`。此操作不可恢复，不迁移旧表，也不提供回退；角色卡文件、草稿和其他应用数据不受影响。
