# SillyTavern Card Creator 使用指南

这份指南面向第一次接触本项目的用户。读完后，你应该能理解软件能做什么、如何从零创建角色卡、如何导入清理旧卡、如何使用 AI 辅助编辑，以及如何把成品导出到 SillyTavern。

## 这个软件适合做什么

SillyTavern Card Creator 是一个本地优先的 CCv3 角色卡编辑器。它主要解决这些问题：

- 从空白开始制作 SillyTavern 角色卡。
- 整理已有 JSON、PNG/APNG 或 CHARX 角色卡。
- 把旧版 V1/V2 角色卡迁移到 CCv3。
- 编辑提示词、开场白、世界书和资源信息。
- 使用 AI 辅助诊断、补全、改写和清理角色卡。
- 在导出前检查结构错误、警告、prompt preview 和 token 占用。

它不是 SillyTavern 本体，也不负责运行聊天；它专注于角色卡制作、整理和导出。

## 启动应用

```bash
pnpm install
pnpm tauri dev
```

只调试前端时：

```bash
pnpm dev
```

默认 Vite 地址是 `http://127.0.0.1:1420`。

Windows PowerShell 如果拦截 `pnpm.ps1`，使用：

```bash
pnpm.cmd install
pnpm.cmd tauri dev
pnpm.cmd test
pnpm.cmd build
```

## 界面区域

应用的主要编辑区域按角色卡制作流程组织：

- **项目**：新建、打开、保存、导入、导出和查看最近文件。
- **基础**：名称、昵称、作者、版本、标签、来源和创作者备注。
- **提示词**：角色描述、性格、场景、示例对话、系统提示词和后置历史指令。
- **开场白**：首条消息、备用开场白和群聊开场白。
- **世界书**：世界书设置与条目，包括标题、触发词、正文、插入顺序和高级触发选项。
- **资源**：封面、背景或其他资源引用。
- **预览**：查看角色卡数据和 prompt preview。
- **Token 统计**：查看总 token、分区 token、最大字段、开场白 preview 和世界书条目占用。
- **校验**：查看阻塞性错误、兼容性警告和结构提示。
- **设置**：配置 AI 服务、模型、推理模式、输出长度和超时。

## 从零创建角色卡

1. 在项目页新建空白角色卡。
2. 在基础页填写角色名、作者、版本和标签。名称是最重要的识别字段，建议先写。
3. 在提示词页填写角色描述、性格和场景。
4. 在开场白页写首条消息。首条消息应该能直接开启对话，最好包含场景动作、语气和给用户回应的钩子。
5. 如果角色有可复用设定、阵营、地点、规则或长背景，在世界书页创建条目。条目正文应当能独立作为 prompt 片段使用，触发词只负责触发。
6. 如果想让 AI 协助起草，可以在 AI Edit 模式选择“一键补全”或“角色卡体检”等工作流，再补充设定要求，确认预览后应用改动。
7. 在预览页查看 prompt preview，确认宏如 `{{char}}` 和 `{{user}}` 的使用符合预期。
8. 在 Token 统计页查看哪个区域占用最高。
9. 在校验页处理错误和警告。错误优先修复，警告根据实际用途判断。
10. 保存或导出 JSON、PNG/APNG 或 CHARX。

## 保存和导出

应用会把草稿自动保存到本机。需要写入磁盘时，使用顶部保存按钮、项目页保存按钮、`Ctrl/Cmd+S` 或右键菜单里的保存。

保存逻辑会根据当前编辑目标自动选择行为：

- 当前卡片来自 JSON 文件时，保存会写回同一个 JSON。
- 当前卡片来自 PNG/APNG 时，保存会把当前 CCv3 元数据写回同一个图片文件。
- 当前卡片来自 CHARX 时，保存会写回同一个 CHARX。
- 新卡或本地草稿会打开保存对话框。

项目页的“导出 JSON / PNG / CHARX”是另存为流程，每次都会让你选择目标位置。导出时会从卡片元数据中移除内嵌 `data:image/...` 图片资源，避免 JSON 或 PNG 元数据过大导致 SillyTavern 报“文件可能无效或已损坏”。如果导出 PNG，封面仍会作为 PNG 图片本体写入，不需要在 JSON 元数据里重复保存；导出器也会剥离部分可能影响导入兼容性的 PNG 来源信息块。保存完成后，封面资源仍会保留在编辑器草稿中，方便继续预览、修改和再次保存。

项目页的最近文件记录保存的是本机绝对路径。如果文件被移动、重命名或删除，再点击该记录时，应用会提示文件不存在并从最近列表移除；这不会删除任何磁盘文件。

## 检查更新

安装版应用会在启动时检查 GitHub Release 中的最新版本。发现新版本后，界面会提示你确认下载和安装；安装完成后应用会重启。

在设置页可以关闭“启动时自动检查更新”，也可以手动点击“检查更新”。

如果你是从源码或开发模式启动，应用只会提示 GitHub 上有新版本，不会自动修改本地 Git 仓库。需要更新源码时，请手动拉取最新代码并重新构建。

## AI 功能

AI 功能需要先在设置页配置 OpenAI 兼容接口：

- Provider profile
- Base URL
- API Key
- Model
- Streaming
- Reasoning display
- Thinking mode 和 effort
- Max output tokens
- Timeout

点击“获取模型”会加载服务端返回的模型列表，并默认选择第一项。默认模式下模型字段是不可手动输入的下拉菜单；如果需要填写未返回的模型名，勾选“手动输入模型”后可以直接指定。

配置后先运行连接测试，确认服务可用。

### Guide 模式

Guide 模式用于普通问答和写卡建议。它不会修改角色卡，适合问：

- 这个字段应该怎么填？
- 当前角色卡有哪些明显问题？
- 哪些字段 token 占用最高？
- 世界书条目是否太长？
- prompt preview 大概是什么样？
- 这张卡适合补哪些开场白？

当前基线版本的 Guide 模式只根据发送给模型的上下文生成普通回答。

### Edit 模式

Edit 模式用于实际修改角色卡。它会要求模型返回结构化 JSON patch，并在界面里展示：

- AI 返回的 JSON 修改计划。
- 应用修改后的 normalized JSON。
- 字段差异预览。

只有用户确认后，修改才会写入当前角色卡。建议把 Edit 模式用于明确任务，例如：

- 补全空字段。
- 改写角色描述。
- 生成备用开场白。
- 根据资料提取角色卡。
- 修复一致性问题。
- 优化 token 占用。
- 构建或整理世界书。

### 编辑目标

Edit 模式支持在指令中使用 `@` 限定修改范围。常用目标包括：

- `@基础`：名称、作者、版本、标签和创作者备注等基础字段。
- `@提示词`：角色描述、性格、场景、示例对话、系统提示词和历史后指令。
- `@开场白`：首条消息、备用开场白和群聊开场白。
- `@世界书`：整个世界书。
- `@世界书条目名`、条目序号、条目 ID、标题/备忘录或关键词：某个具体世界书条目。
- `@当前字段`：最近聚焦的 AI 字段。
- `@选中文本`：最近可用的字段选择文本。
- `@空字段`：仅允许补空字段。
- `@弱字段`：仅允许修改较短或较弱的文本字段。
- `@错误`：优先修复当前校验结果关联的字段。

输入 `@` 时会出现候选菜单，可以用方向键选择，按 Tab 或 Enter 填入。应用仍会在本地过滤不允许的 patch 路径。

### 快捷工作流

在 Edit 模式的输入区，可以点击底部 `+` 菜单，或输入 `/` 打开工作流命令。常用工作流包括：

- 角色卡体检
- 一键补全
- 资料提取
- 一致性修复
- Token 优化
- 世界书构建
- 导入清洗

选择工作流后，可以继续输入额外要求。实际请求发送时，应用会把工作流默认指令和你的额外要求合并。工作流结果仍然走 JSON patch 预览和用户确认流程。

### 字段级 AI 助手

部分长文本字段聚焦时会出现字段级 AI 按钮。它适合做局部操作：

- 润色和扩写
- 重写
- 补全
- 缩短
- 翻译
- 强化角色语气
- 冲突检查
- 关键词提取
- 生成变体

字段级 AI 的结果也会先展示 diff 预览，确认后才应用。

## 导入和清理旧卡

推荐流程：

1. 在项目页导入 JSON、PNG/APNG 或 CHARX。
2. 先打开校验页，查看是否有结构错误。
3. 到基础页和提示词页检查乱码、重复内容、空字段和不符合 CCv3 语义的内容。
4. 到世界书页检查条目标题、触发词、正文、启用状态和插入顺序。
5. 使用预览页和 Token 统计页检查最终 prompt 是否过长或重复。
6. 需要批量清理时，可以使用 AI Edit 模式里的导入清洗工作流。

## 常见问题

### AI 连接失败

检查 Base URL、API Key、模型名和网络环境。OpenAI 兼容接口通常需要 `/chat/completions` 兼容行为。

### Edit 模式会不会自动改坏卡片？

不会直接写入。Edit 模式会先展示 JSON patch 和 diff，用户确认后才应用。应用层还会过滤不允许的路径，例如 raw `/data`、`/spec` 和 `regexScripts`。

### 导入后有警告是否一定要修？

不一定。错误通常代表结构不合法或会影响使用；警告多是兼容性、格式或潜在问题，需要结合卡片用途判断。

### PowerShell 不能运行 pnpm

使用 `pnpm.cmd` 版本的命令，例如：

```bash
pnpm.cmd test
pnpm.cmd build
pnpm.cmd tauri dev
```

## 隐私和数据边界

应用是本地优先的编辑器。草稿、最近打开记录和 AI 设置保存在本机。使用 AI 功能时，你发送给模型服务商的内容可能包含当前角色卡、校验信息、对话上下文或你输入的指令。不要把不想发送给第三方模型服务的内容放进 AI 请求中。
